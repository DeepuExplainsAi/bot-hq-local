# Part 8: bug and error check (by reading code + CI; no features, no UI change)

Only existing checks were run, in CI (nothing heavy in the sandbox): typecheck, build, security 51, smoke, verify, Electron smoke, installers (see HANDOFF.md for run ids). I did not test offline / disk-full / interrupted installs by actually causing them; those rows are from reading the code.

| # | Area | Finding | Status |
|---|---|---|---|
| 1a | Bind address | Server: `env.host` defaults to 127.0.0.1 in desktop mode (smoke step "listens on 127.0.0.1 only", also checks the LAN address refuses). Bot-browser DevTools: `remote-debugging-address=127.0.0.1`; port probe on 127.0.0.1; Hermes gateway: `API_SERVER_HOST=127.0.0.1` (smoke checks). `/mcp` refuses non-local peers. | OK, no change |
| 1b | Secrets | Install secret `secret.key` and `tools.enc` are 0600 (AES-GCM); app tokens only in the encrypted file (smoke checks files, configs and log). Server gets only an allow-listed env, no cloud keys. gitleaks: no leaks in history. Bot `.env` (API key for the local gateway, any model key the user adds) is plain text 0600 in the app-data folder, as Hermes expects. On Windows the 0600 mode does nothing (folder ACL of the user profile applies). | OK; Windows file mode: not fixable by chmod, left |
| 2a | Hermes install, error shown | Failure showed an error page with no way to retry (restart needed). | **Fixed**: dialog with Retry / Quit (`desktop/main.cjs`), loops until success or quit. |
| 2b | Half-installed state | `installed.json` is written last; the source folder is wiped before each attempt; `uv sync --frozen` is re-run on retry. An interrupted run is never taken as installed. One gap: an interrupted copy of `uv` itself left a file that later runs trusted. | **Fixed**: copy to `uv.part`, then rename (`desktop/hermes.cjs`). |
| 2c | Offline / disk full | Download and `uv` errors are passed on with the last 12 lines of their output ("HTTP …", "No space left…"); the Retry dialog tells the user to check internet and disk. Not exercised by a real offline or full-disk test. | Not tested |
| 3a | Orphans on normal quit | Quit stops the server, which stops gateways (taskkill /T on Windows, process groups elsewhere) and bot browsers (smoke "quitting the server stops its gateways and browsers"). | OK |
| 3b | Orphans after a hard kill | If Electron or the server is killed with SIGKILL / Task Manager, gateways and bot browsers keep running. The next start adopts a healthy gateway (engine.ts), so data is not corrupted, but the processes stay until the next quit or a reboot. | Not fixed (needs a watchdog; larger than a bug fix) |
| 3c | Second launch | `requestSingleInstanceLock`: the second launch exits and focuses the first window; one data folder, one server. | OK (read, not run) |
| 4a | Paths with spaces / non-ASCII | Every child process is started with an argument array (no shell string), paths via `path.join`; the Windows installed-app smoke ran from a path with a space (`Bot HQ.exe`). A Windows username with non-ASCII letters was not tested; `PYTHONUTF8` is passed to Hermes. | Not tested for non-ASCII |
| 4b | Port in use | Preferred 8787, else a random free port (`pickPort`); bot browsers search upward from 9200; gateways use a free-port search. A race between probe and bind is possible but tiny; a bind failure shows the "server did not start" error page. | OK |
| 5 | `~/.hermes` | Desktop mode sets the shared home to `<data>/hermes-shared`; every gateway has `HERMES_HOME=<data>/engines/<bot>`; smoke asserts no `~/.hermes`; real Hermes on Windows and macOS (hermes-real) also left it absent. | OK |
